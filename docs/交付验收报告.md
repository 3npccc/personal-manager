## 五、架构要点

```
lib/
├── main.dart              程序入口
├── app.dart               MaterialApp（主题 + 中文 locale + 标题）
├── app_shell.dart         NavigationRail + IndexedStack 九页外壳
├── core/
│   ├── database/          drift：15 表 + 15 DAO + 建库/内置分类
│   ├── navigation/        导航目的地定义
│   ├── providers.dart     全局 provider（数据库 / DAO / 设置）
│   ├── theme/             浅色 / 深色主题
│   └── utils/             格式化 / 日期工具
├── features/<模块>/
│   ├── services/          业务服务（纯逻辑，可单测）
│   ├── providers/         Riverpod provider（读侧流 + 写侧 actions）
│   └── ui/                页面与对话框
└── shared/                共享 widget（卡片 / 空状态 / 表单字段…）
```

**分层原则**：`services`（纯逻辑，无 Flutter 依赖）→ `providers`（状态）→ `ui`（渲染）。
测试相应分三层：**DAO 层**（真实临时库）、**服务层**（纯函数 + 内存库）、
**UI 层**（注入假服务，不碰真实文件 IO）。

### 三个关键设计决策

1. **金额以整数「分」存储**（`amountCents`）—— 浮点存钱有精度误差，整数分零误差。
2. **恢复前强制自动兜底备份**到 `auto_backup_before_restore\` —— 误操作可回滚。
3. **版本三重校验**（formatVersion / schemaVersion / 字段完整性）**全部在写库之前** ——
   校验失败**绝不覆盖**现有数据。

## 六、已知限制（如实列出）

| # | 限制 | 影响 | 说明 |
| - | ---- | ---- | ---- |
| 1 | **全量测试必须串行跑**（`--concurrency=1`） | 仅影响开发时的测试速度 | 16 核机器默认可并行 15 个 isolate，每个都构建整壳 9 页 → Dart VM 堆溢出（OOM）。串行后**测试一个不少**，只是慢一点。**这是环境内存压力，不是代码缺陷**（每个测试文件单独跑都全绿） |
| 2 | **概览首页暂未做跨模块聚合** | 首页只显示今日待办 / 本月收支 / 笔记统计三块 | 按需求确认：跨模块聚合（进行中项目数 / 今日是否打卡）留到后续迭代 |
| 3 | **CSV 不支持恢复** | CSV 仅用于查看 / 分析 | 恢复**必须**用 JSON（CSV 丢失类型与关联信息） |
| 4 | **单实例使用** | 同一时间建议只开一个窗口 | SQLite 单文件并发写可能锁冲突 |
| 5 | **发布需拷整个 Release 文件夹** | 不能只拷 exe | Dart 运行时（`flutter_windows.dll`）与 `data\` 资源在同目录 |
| 6 | **窗口标题为中文「个人管理」，exe 文件名仍为 `personal_manager.exe`** | 无功能影响 | 改 exe 名需同步改 CMake 目标名，风险大于收益，故保留 |

## 八、release 构建

构建命令（见 `stage5_build.bat`）：

```bat
flutter clean
flutter pub get
dart run build_runner build --delete-conflicting-outputs
flutter analyze
flutter test --timeout=90s --concurrency=1
flutter build windows --release
```

产物路径：`build\windows\x64\runner\Release\`

**发布时复制整个 `Release` 文件夹**，不要只复制 exe。
